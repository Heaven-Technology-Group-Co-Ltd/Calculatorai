• Root cause: Netlify Build's post-build secret scanning core step (`secrets_scanning`) flagged false-positive matches for `SMTP_USER` and `SMTP_HOST` because non-credential environment variables were marked with `is_secret: true` in site settings. The scanner treated the literal values of `SMTP_USER` ("resend") and `SMTP_HOST` ("smtp.resend.com") as leaked secrets when they occurred across UI components, logs, and compiled server bundles, causing the build to fail with a severityCode 2 (`user-error`).
• Fix: Added `netlify.toml` configuring `[build.environment]` with `SECRETS_SCAN_OMIT_KEYS = "SMTP_USER,SMTP_HOST,SMTP_FROM,SMTP_PORT,NEXTAUTH_URL,SUPABASE_URL,GOOGLE_CLIENT_ID"`, omitting non-sensitive metadata from secret scanning while maintaining protection for genuine secrets (passwords, tokens, API keys). Also explicitly declared build settings and `@netlify/plugin-nextjs`.
